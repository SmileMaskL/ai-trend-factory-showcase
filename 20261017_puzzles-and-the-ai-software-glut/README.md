# AI 소프트웨어 글루트 레이더 (PyPI)

## 한 줄 설명
PyPI의 공개 "신규 패키지" 피드를 매일 스캔해, 동일 저자의 대량 퍼블리시 + 보일러플레이트(내용 없는) 설명 패턴을 수치화한 "글루트 지수"와 함께 텔레그램으로 알려주는 무인 레이더입니다.

## 왜 이 트렌드에서 이 아이디어가 나왔나
오늘의 트렌드 "Puzzles and the AI Software Glut"(HN, points=1/comments=1)는 신호 자체는 약하지만, 핵심 주장("AI가 소프트웨어 생산 비용을 극단적으로 낮춰서 저품질/무의미한 소프트웨어가 폭증하고 있다")은 검증 가능한 데이터로 추적할 가치가 있습니다. 이 프로젝트는 그 주장을 추상적인 토론이 아니라, 실제 패키지 저장소(PyPI)에서 측정 가능한 두 가지 proxy로 바꿨습니다:
1. 신규 패키지 중 설명이 비어있거나 보일러플레이트인 비율("글루트 지수")
2. 짧은 시간에 한 저자가 다수의 신규 패키지를 쏟아내는 패턴("대량 퍼블리시")

기존에 만든 GitHub 트렌딩/OSS 큐레이션 봇은 "품질 좋은 신규 프로젝트 발굴"이 목적이라 정반대의 니치(저품질/스팸성 공급 과잉 감지, 데이터 소스도 PyPI 신규 패키지 피드로 전혀 다름)이며, 다른 블랙리스트 프로젝트들과도 주제·데이터 소스가 겹치지 않습니다. 참고로 대량 퍼블리시 + 보일러플레이트 패턴은 타이포스쿼팅/디펜던시 컨퓨전 공급망 공격의 전형적인 전조 신호이기도 해서, 부가적으로 보안 리서처에게도 쓸모가 있습니다.

## 필요한 환경변수
- `TELEGRAM_BOT_TOKEN` : 기존 파이프라인에 이미 설정되어 있는 텔레그램 봇 토큰 (그대로 사용)
- `TELEGRAM_CHAT_ID` : 기존 파이프라인에 이미 설정되어 있는 텔레그램 채팅 ID (그대로 사용)

별도의 새 API 키는 필요하지 않습니다. PyPI RSS/JSON API는 인증 없이 무료로 사용 가능합니다.

## 실행 방법
```bash
python3 run.py
```
- `https://pypi.org/rss/packages.xml`에서 최신 신규 패키지 목록을 가져옵니다.
- 이미 처리한 패키지는 `data/seen_packages.json`으로 걸러냅니다(최대 60건/실행).
- 각 패키지에 대해 PyPI JSON API(`/pypi/<name>/json`)로 저자/요약을 조회합니다(요청 간 0.3초 대기, 매너 준수).
- "보일러플레이트 설명 비율(글루트 지수)"과 "저자별 대량 퍼블리시"를 계산해 텔레그램으로 1건의 요약 메시지를 보냅니다.
- 한 번 실행하면 수집→분석→알림→종료하는 배치 스크립트이며, 서버/데몬으로 띄우지 않습니다.

## 커스터마이징
`watchlist.json`에서 다음을 조정할 수 있습니다:
- `trivial_phrases` : "내용 없음"으로 판정할 보일러플레이트 문구 목록
- `trivial_min_length` : 이 길이(문자 수) 미만 설명은 자동으로 "글루트"로 판정
- `mass_publish_threshold` : 한 저자가 이 값 이상 신규 패키지를 올리면 "대량 퍼블리시"로 알림

## 현실적인 수익화 전략
- **대상**: OSS 공급망 보안 리서처, "AI와 소프트웨어 품질" 주제를 다루는 뉴스레터/블로그 운영자.
- **방법**: 매일 쌓이는 글루트 지수를 주간 단위로 모아 "이번 주 PyPI 글루트 리포트"로 블로그/뉴스레터에 발행 → 보안 도구 벤더(디펜던시 스캐너 등) 스폰서십 또는 소액 유료 구독 시도. 지수 자체를 트위터/X에 주기적으로 포스팅해 레퍼런스 트래픽을 모으는 것도 가능.
- **난이도/소요 시간**: 스크립트는 바로 동작하며 추가 개발이 거의 불필요(난이도 낮음). 다만 PyPI 신규 패키지 피드는 노이즈가 많아(합법적인 신규 프로젝트도 설명이 짧은 경우가 흔함) 오탐이 상당히 섞이며, 이를 "믿을 수 있는 리포트"로 다듬으려면 최소 2~4주간 수동 검증/튜닝이 필요합니다. 돌리자마자 수익이 나는 구조는 아니고, 데이터를 사람이 가공해 콘텐츠·리드마그넷으로 만들어야 의미 있는 수익화가 가능한 수준입니다.
